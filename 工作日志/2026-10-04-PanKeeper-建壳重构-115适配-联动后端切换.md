## 一、建壳转存重构（用户定稿："用资源名新建文件夹，剥壳转入"）

- **语义变更**：快速/普通转存的 `with_shell` 不再"整壳转 + rename_dir 事后改名"，改为在
  save_dir 下按「更名值 → 资源名(pansou 名) → 分享真实目录名 → "分享资源"」优先级**新建**
  文件夹、分享内容剥壳转入。三盘同构实现（baidu/quark/pan115 各自 `_save_with_shell`）。
  动机：① 搜索源名字是资源名不是分享目录名，整壳转过来对不上；② rename_dir 事后改名
  实测被可见性延迟/风控拽失败（errno=2 案）；③ 整壳转 transferred 只有壳一条，
  run_watch 拿壳名查 QMS 逐文件记录永远查不到。
- 非单壳"1 文件夹+散文件"仍剥原壳（防套娃）；多文件夹混杂连原结构进新壳。
- **删除 rename_dir 事后改名整条链**（baidu/quark/115），没有改名环节可失败。
- 记录展示随之归位：`t["files"]` 只数文件（目录条目不计）——"完成 N/M"、队列"N 项"
  不再把壳算进去（1 个文件显示 1/2 的案）。

## 二、115 网盘适配器补全（Cookie 路线，全部实测）

- **建壳承接**：单壳判定（根层 1 目录）、整目录接收（一个 fid 带整棵子树，省请求防风控；
  壳条目本身绝不收——套娃防线）、剥原壳、正则改名时退回逐文件。
- **转存后改名**：`POST webapi/files/batch_rename`，表单必须**三字段齐**：
  `fid` + `file_name` + `files_new_name[<cid>]`（files/rename、proapi 全报"服务器开小差"，
  连环踩四轮，最终从 115driver/alist 源码找到正确形态）。
- **目录管理**：建目录参数是 `cname`（dirname 报"目录名称不能为空"）；删除走
  `webapi/rb/delete`（移入回收站）；rename 同上。
- **own-dir 语义**（/files 接口）：响应是扁平 list、count 在顶层；条目 id 在 **cid**
  （fid 是分享 snap 侧字段）；文件判定靠 sha/sha1。与 snap 两套别混。
- **snap 双形态**：带 cid（子目录）list/count 在顶层；不带 cid（根层）嵌套在 data 里。
- **summary**：会员 = get_user_aq 的 vip 字段；容量 = `115.com/index.php?ct=ajax&ac=get_storage_info`
  （按空间分区求和）。普通用户显示灰字胶囊。
- **风控**：限速 1s→**2s**、冷却 60s；HTTP 302 = 账号级临时封禁（实测撞过一次：密集请求
  后探活即 302），适配器直接报人话"暂停 10-30 分钟"，别显示"响应非 JSON"。

## 四、STRM 跟随 QMS 自动配对 + 定向同步

- **STRM 不再让用户选**（转存配置页/普通转存弹窗/快速转存预览全部移除 STRM 选择项）：
  配了 QMS，整理成功自动定向生成 STRM，失败不生成。STRM 目标 = QMS 侧自动配对：
  刮削路径的整理目标根（dest_path）↔ 同步路径的 remote_path（同一条链），结果缓存 5 分钟。
- **定向同步**：QMS 的 `POST /api/sync/manual`（ID=0 临时任务）只扫指定目录。定位方法：
  刮削记录的 `new_path`（相对整理目标根）+ 刮削路径 `dest_path` = 整理后的目录——
  不用猜 QMS 把文件搬哪了。落盘 = 同步路径 local_path + openlist 完整路径，与常规
  同步布局天然一致。任何失败回退整路径同步（STRM 能力不丢）。
- ⚠️ 临时任务（TmpSyncPath）跳过 Emby 刷新/关联刮削/last_sync_at 更新——PanKeeper 在
  90s 后借 QMS 配置的 Emby 地址/ApiKey 补一次 Library/Refresh（尊重 QMS 开关）。
- ⚠️ openlist STRM 内容主机 = QMS 全局「STRM 基础URL」——被配成了 8020（QMS API 端口），
  已修正为 5544（openlist），并重跑定向重新生成。
- 反查 WARN（"入口 ID 与任务携带的 ID 不一致，改用反查结果"）：PanKeeper 传 path_id="0"
  占位，QMS 自动反查自愈，无害。
- "仅 STRM"模式（不刮削直生成）整体删除。
